# CachyOS NVIDIA Suspend Fix + Shelly GUI Repair

## Context

David returned with two problems on his freshly reinstalled CachyOS system (ASUS ROG Strix, Intel UHD + NVIDIA RTX 4060 Max-Q, COSMIC desktop, Limine bootloader, LUKS encryption with TPM2 auto-unlock, Secure Boot enabled):
1. Black screen after sleep/hibernate — system completely unresponsive
2. Shelly GUI (package manager) hangs with spinning dot, CLI works fine

## What we did

- Rex diagnosed the NVIDIA suspend issue: services disabled, missing kernel params
- David enabled `nvidia-suspend.service`, `nvidia-resume.service`, `nvidia-hibernate.service`
- David created `/etc/modprobe.d/nvidia-power-management.conf` with `NVreg_PreserveVideoMemoryAllocations=1`
- David added `nvidia-drm.modeset=1 nvidia-drm.fbdev=1` to kernel cmdline via `/etc/default/limine`
- David ran `limine-mkinitcpio` + `limine-enroll-config` to rebuild initramfs and re-enroll config checksum
- TPM auto-unlock survived (PCR 7 only enrollment)
- Suspend/resume tested and confirmed working
- David disabled hibernate in `/etc/systemd/sleep.conf` (AllowHibernation=no, AllowSuspendThenHibernate=no, AllowHybridSleep=no) to prevent failed hibernate from hanging the system
- Diagnosed Shelly GUI hang: missing polkit auth agent (cosmic-osd polkit agent broken by polkit >= 127)
- David reinstalled `cosmic-osd` which pulled the fix for COSMIC's native polkit agent
- Shelly GUI confirmed working after cosmic-osd reinstall
- Discussed hybrid GPU mode: how GPU selection works in Hybrid mode, confirmed Zoom uses Intel (expected behavior), NVIDIA stays in D3 sleep at 2W when idle

## Decisions made

- **Question:** Should we edit `10-chwd.conf` to remove NVIDIA modules from initramfs?
  **Decision:** No. CachyOS Wiki confirms early module loading is correct for Wayland. The fix is to make suspend services work WITH early loading, not against it. Don't touch `10-chwd.conf`.

- **Question:** Use `mkinitcpio -P` or `limine-mkinitcpio`?
  **Decision:** Use `limine-mkinitcpio` — it runs mkinitcpio AND updates limine.conf entries via the limine-entry-tool hook in one step. Required on CachyOS with Limine bootloader.

- **Question:** Fix hibernate or disable it?
  **Decision:** Disable it. Hibernate on hybrid GPU + LUKS + Secure Boot + BTRFS is notoriously finicky. Suspend works perfectly, and that covers the use case. If hibernate is needed later, Path B (adding `resume=` kernel param) is documented.

- **Question:** Install `polkit-gnome` as fallback or reinstall `cosmic-osd`?
  **Decision:** Reinstall `cosmic-osd` first — CachyOS repo has the fix for polkit 127 compatibility. `polkit-gnome` would be the fallback if cosmic-osd's agent still didn't work.

## Insights

- **`limine-entry-tool` cmdline source:** The default kernel cmdline comes from `KERNEL_CMDLINE[default]` in `/etc/default/limine`. `limine-mkinitcpio` regenerates limine.conf entries using this config. Always use `limine-mkinitcpio` instead of bare `mkinitcpio -P` on CachyOS with Limine.

- **`ENABLE_ENROLL_LIMINE_CONFIG=yes`:** After any limine.conf change, MUST run `limine-enroll-config` or system won't boot (config checksum mismatch = boot panic).

- **TPM PCR 7 only:** David's TPM enrollment uses PCR 7 only (not 0+7). This means only Secure Boot state changes break auto-unlock — initramfs/kernel/cmdline changes are safe. This is more flexible than the default PCR 0+7.

- **Pacman keyring corruption:** Keyring corruption (`invalid or corrupted database (PGP signature)`) blocks all package operations. Fix: `rm -rf /etc/pacman.d/gnupg && pacman-key --init && pacman-key --populate archlinux cachyos`.

- **COSMIC polkit agent:** Built into `cosmic-osd`. Was broken by polkit >= 127 (cosmic-session#177). Fixed in cosmic-osd#193. If CachyOS repo has the updated package, reinstalling `cosmic-osd` resolves it.

- **Hybrid GPU utilization:** Linux Hybrid mode is more power-efficient than Windows — NVIDIA GPU sleeps at 2W when idle vs Windows keeping both GPUs active 30-60%. This is by design, not a bug.
